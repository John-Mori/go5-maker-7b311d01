# 送信印と重複排除の分離（2026-09-24 HQ裁定）

## 裁定

- `LeaseQueue.enqueue()` の戻り値は「処理を1件へ収束できたか」の判定だけに使う。
- 送信印は「その受信経路が便を受領した」表示であり、`enqueue=False`（既存・重複）を理由に省略しない。
- 同一Bot・同一絵文字のreactionはDiscord側で1個に収束する。再接続リプレイでも表示件数は増えない。
- Claude閉室など、そもそもClaude配達を受けない経路には送信印を付けない。重複と閉室を同じ `False` で扱わない。

## 背景

Codex専用gatewayとClaude側gatewayが同じDiscord投稿を受ける。Codex側が先に同じ `msg_id` を
enqueueするとClaude側は重複扱いになり、処理は正常に1件へ収束した一方、送信印まで省略された。
原因は「処理の冪等性」と「受領表示」を `added` 一つへ結合していたことだ。

## 回帰条件

- 同じ `msg_id` を2回受信してもqueue行は1件。
- 2回目の受信でも、許可された経路なら正しい送信印の呼び出しが発生する。
- `added` 条件へ戻す故障注入で試験が赤になる。
- Gateway受信ループの帰還・例外は同一プロセス内で再接続する。プロセス消失時の外部監視は1分周期とする。

実行する検査:

```text
python scripts/queue/test_gateway_sendmark.py
python scripts/queue/test_gateway_sendmark.py --mutate dupe
python scripts/queue/test_gateway_restart.py
```
