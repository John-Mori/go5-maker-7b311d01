## 2. 投稿履歴タブの常駐メモリ解放(v=686)★「Xやつべから戻るとリロード」の対策

- **症状**: X/YouTubeへ切替→📋投稿履歴タブへ戻るとページがリロードされる。iOS Safari がメモリ都合でタブを丸ごと破棄→戻ると再構築。
- **対策の考え方**: 離れている間だけ、一番重い**サムネ画像の山(RAM)だけ**を手放す。元画像は端末内に持ったままなので、戻れば手元データで速く組み直る(ネット再取得は不要)。

| 事実 | 在りか(最終確認 v=686) |
|---|---|
| ページ丸ごと空にする対象(v=685) | `affiliate.js:36` `HEAVY_UNMOUNT = { rankBtn, tabCand, tabStock }` |
| 投稿履歴は**子要素だけ**空にする(v=686) | `affiliate.js:40` `HEAVY_UNMOUNT_CHILD = { tabVerify: 'ytClickList' }`(ページには静的な操作ボタンが在るのでページ丸ごとは不可) |
| 入場時に作り直す(空の時だけ=二重描画回避) | `affiliate.js:77` → `window.Go5Verify.render()` |
| render の実体を公開 | `yt-clicks.js:3375` `window.Go5Verify = { render: render }` |
| サムネ元画像は端末内保持(再取得不要) | `yt-clicks.js` 内 `refThumb`(usedImgs/bskyImg/postImgs 由来) |

- **段階**: v=684(背景動画を前面時だけ再生)→ v=685(重いタブをページごと空に)→ **v=686(投稿履歴のサムネ列だけ空に)**。
- **状態**: 入れた(確認待ち)。**「効いた/直った」はChamiのiPhone実機で「戻ってもリロードが減った」を見てから**。実機確認の観点= ①リロード頻度が下がったか ②戻り表示(サムネ・再生数・クリック数・並び順)が壊れていないか。
