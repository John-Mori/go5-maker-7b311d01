## 2. 数え方(定義)
- **発火率** = その週の該当event件数 ÷ その週の総返信便数。★母数は「その場のワンライナー」で数え直さず、`00_AI-HQ` 各部屋 memory の返信便を数えた値を添える(規律§1)。
- **偽陽性率** = 誤検知(実際は正常だった発火)件数 ÷ 該当event件数。
  - ★偽陽性は**機械だけでは確定しない**。発火の中から n件(既定 30件・少なければ全件)を目視し、正常だった割合を出す。**目視した件数と誤爆の中身を必ず添える**(規律§1・A-11)。
  - naming の「話者自身の名」「名乗りタグ行」由来、self_check 灰色②の「その部屋の人格が自分の名で名乗った便」は**構造的偽陽性**=先に除いてから率を出す(このズレが 813件[17.45%]→204件[4.38%] の差を生んだ・出所=元便)。

## 3. 格上げ判定(各ゲート「警告のみ→置換/再生成」)
1. **発火率が実害を伴う水準か**(そもそも問題が出ているか)。
2. **偽陽性率が閾値未満か**。初期しきい値= **偽陽性率 5%未満**(暫定・実運用の数字で見直す)。5%以上なら格上げせず、まず絞り込み条件を足して偽陽性を下げる。
3. 2条件を満たして初めて置換/再生成へ格上げを**提案**(実装は基盤部門=イージス研究室/プラットフォームSE。QAは判定と数字を出す)。
- **self_check の灰色4条件**(`self_check.gray_reasons()`: ①ゲートJ発火 ②漢字フル名 ③英字20〜34字中間帯 ④nonjp再生成2周目)の絞り込み/拡張も、`reasons` 別の発火率を数えてから決める。広げるなら発火率を測ってから(元便のデブライネの依頼どおり)。
