# 上申: スプレッドシートの「0のみ/空白のみ」列の削除依頼

- 起票: アメス(留守番) / 2026-07-22
- 出典: Chami依頼「0しか入ってない、もしくは空白しかないデータ列のデータをスプレッドシートから消して。消してと言ったら消して」
- 回送先: 研究室HQ → AD研究室(モドリッチ) → system-engineer(α)
- 留守番の判断: **範囲外**(不可逆・外部・削除／ライブデータ判断が必要)。憶測での削除はしない。

## 事実(調査済み・読むだけで確認)
1. 列削除の**正規経路は既にある**: `gas/コード.gs`
   - `CLEANUP_COLUMNS`(現状 `['特別期間(手動)','サムネ/フック種別(A/B)','CTA・リンク提示方法','Blueskyラベル']`)
   - `?action=cleanup_columns` で既存シートから該当列を削除(冪等)。コードが唯一の正。
   - → 実行には **GAS編集＋デプロイ＋本番シートへの破壊操作** が伴う。

2. **「0/空白でも消してはいけない列」がある**(同ファイル31行目のコメントが明記):
   - 分析数式の計算元 = 承認率% / CVR / EPC / RPM が参照する **FANZA成約・報酬系**の列
   - **post_uri**(反応の自動更新に必須)
   - 新規投稿では 再生数・クリック・成約が **0/空白なのが正常**。
   - → 「0か空白だから消す」を機械適用すると**分析式が壊れる**。どの列が真にゴミかは
     ライブデータの実測＋数式依存の判断が要る。

## 依頼したい判断/作業(system-engineer)
- 記録_ch1 / 記録_ch2 の全列を実測し、**全行0 or 全行空白**の列を抽出。
- そのうち「分析数式の入力でない・自動更新に不要」な列だけを削除候補に確定。
- `CLEANUP_COLUMNS` へ追記 → `cleanup_columns` で反映(要デプロイ)。
- 迷う列は消さずChamiへ一覧提示(「削除しない、退避する」原則)。

3. **削除してよいのは"死んだゴミ列"だけ**。以下は 0/空白でも**消すな**(Chamiの意図は死列の掃除であり、

5. 判断に迷う列は**消さず**Chamiへ一覧提示(「削除しない、退避する」原則)。
