## ★系列の分断= 競合"動画"日次の速度は `measDays[0]!=1`(N日ならしの行)を初速と1本の折れ線に乗せない(分析部門+ad研究室の実務規律。★切るのは真因の「分母」であって経路ではない。経路(GAS→yt-dlp)での恒久分断は9/6の実物が付くまで"暫定")

- **何**: 競合_日次の速度(views/measurementDays)は 8/18 medAll=798.5・medMax=189376 → 9/5 medAll=47.0・medMax=10148 と一桁落ちている。これは競合が急落したのではなく、**9/5行だけ `speed` の分母(`measurementDays`)が 1→18 になった段差**(=真因は下の【なぜ】③・詳細はそこ)。**`measDays[0]!=1` の行を初速と同じ折れ線で繋ぐと「9月に競合が失速した」と誤読する。**
- **なぜ(主因=確定寄り・ad研究室モドリッチ 2026-09-05 読み取りで絞り込み)**: **③欠測による分母の伸び=`speed` の分母 `measurementDays` が 1→18 になっただけ(旧称「スナップ齢」は撤回済みの別説名なので機構名へ改称・中身は同一)。** `medAll`/`medMax` が測るのは累計再生数ではなく `speed`=直近2スナップ間の増分÷経過日数(`scripts/analysis/competitor_daily.py:465` / `gas/競合.gs:963`)。競合日次は 8/18 で止まり 9/5 に再開(18日欠測)=9/5行だけ 18 で割られている。**検算= medMax 189376/10148=18.66・medAll 798.5/47.0=16.99 ≒ 18**(gas/競合.gs:938 コメント「欠測日は経過日数で割って1日平均へ直す」通りの設計挙動=バグではない)。18日平均は初速より構造的に小さく出る(公開直後に伸びて後は寝る)ため 16.99〜18.66 に幅が出る。①計測時刻・②取得元(yt-dlp)は主因ではない。★**母集団の入れ替わり(「漫画ライク」新規・「きらきら1番劇場」消滅・あにめ漫画ストック43→19本)は実在するが桁落ちの主因ではない**=残存全ch(あにめ漫画ストック986→16 / グッとくる1コマ2069→68 / 今宵のバズ同人794→31.5 等)が一様に1〜2桁落ちており、母集団差でこの一様さは出ない。
- **答え合わせ(未確定を閉じる条件・C-041)**: **9/6 のスナップが入れば `measurementDays` は 1 に戻り `speed` は元の桁へ戻るはず。戻れば③で確定。戻らなければその時こそ母集団/取得段の話**=それまで結論を出さない。行に持たせた `measDays`[中央値,最大,≠1本数] が 1 に戻るかで機械的に読める(2026-09-05 計装済)。
- **どうする**: 朝ブリーフ/トレンド図は **分母(`measDays[0]`)が同じ区間どうしでだけ比較**する。**9/5 の 47.0 と 8/18 の 798.5 を同じ折れ線に乗せない**(単位が違う=前者は18日ならしの1日平均・後者は1日ぶんの伸び)。★**`measDays[0]!=1` の行は「N日ならし」印として初速比較から外す**(競合失速と誤読しない)。
- ★**経路(GAS→yt-dlp)での恒久的な別系列は"暫定"=9/6の実物で機械的に決める**(取得元が YouTube Data API→yt-dlp に変わったのは事実だが、`view_count` の定義・取得段が旧経路と同じである保証はまだ無い=そこは当室にも材料が無い)。分岐条件=
  - **9/6 に `measDays[0]` が 1 へ戻り、かつ `speed` が 8/18 の桁(medAll 数百台)へ戻った → 経路差は無い。旧経路値と繋ぎ直す(別系列は解除)。過去1か月ぶんの比較材料を捨てない。**
  - **戻らなかった → 経路差が実在。そこで初めて恒久の別系列(別色・凡例に経路名)にする。基準線も新経路で引き直す。**
  - 跨ぐ変化率は、9/6のこの判定が付くまで出さない。

## シート・ID規約

- **シート実タブ名=「月詠み」「宵桜艶帖」**(記録_ch1/ch2という名前のタブは無い。gas/コード.gs sheetName_)。
- **投稿日時列=YouTube実投稿時刻**(Chami明示2026-07-13。Blueskyの投稿時刻は意図的にズラしてあり分析に使わない→知見.md)。
- **ID体系は2系統ある[実測 2026-07-18訂正]**: historyのvideoId(post_id)=内部ID(acc1-/acc2-接頭辞つき)。**deltasのキー=生のYouTube videoId(接頭辞なし)**。突合はhistoryの**youtubeUrl**末尾で行う(deltas単独ではチャンネル分離不可)。リビルドはrebuildBaseClicksを考慮。
