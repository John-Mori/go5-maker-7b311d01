## 1. 絶対規約(破ると"直された"になる・最優先)

- **「よくあるClaudeの紫デザイン」を使わない(恒久・Chami指示2026-07-03)。** モーダル/オーバーレイ/
  ボタン等の新規UIに紫を使わない。禁止色の例: `#5b3f8e / #2a1a4e / #1a1a2e / #d4b3ff / #c4a0ff`。
  → アプリ配色(§2)に合わせる。※アカウントテーマの紫(月詠み=#241a3d 等)は**別枠でOK**。
- **UI文言の括弧は必ず半角 `()`。全角 `()` 禁止**(CLAUDE.md・system-engineer BOOT)。
- **時刻表示は日本時間(JST)**。`toISOString()`/UTCをそのまま表示に出さない(Chamiの体感と9hズレる)。
  JSは端末ローカル(`getHours()`等)。例外=Cloudflare枠リセット等のUTC固定値は集計UTC・表示JST併記。
- **座標系を崩さない(§3)。** px/vh/vw を直接使わない。プレビューと書き出しは同一Canvas・同一式。
- **締めの言葉に「刻んだ」系を使わない**(2026-07-16・全キャラ廃止)。記録は「(自然な完了の言葉)。(ファイル名)」。

## 3. 座標系(動画Canvasの最重要規約・崩さない)

- 基準フレーム **W=1080 / H=1920(9:16)が唯一の基準座標系**。`<canvas width height>` も一致。
- 位置・フォントサイズは `H×係数` / `W×係数`。旧絶対px定数は `U(v)=v*H/1280` で換算。
- **プレビューも書き出しも同一Canvasに同じ式で描画** → PC/スマホ/書き出しで一致(CSSは9:16を一様縮小表示するだけ)。
- 縦オフセットは `OFF` オブジェクトで一元管理(`OFF.whole`/`OFF.textAuthor|Detail|Title`等)。
- `document.fonts.ready` 後に再描画(フォールバックフォント計測ズレ防止)。

## 4. コントロール/操作系の好み

- **位置調整は ＋/− ボタン式(スライダーではない)**。プレビュー横で見ながら微調整(スマホは sticky)。
  (v11でスライダー→＋/−へ刷新。Chamiの確定好み)
- 段別に独立制御(①作者名/②誘導文/③大タイトル)。帯は各段のテキストに統合(帯だけ別に動かさない)。
- **2行モード**: 作者・大タイトルに「2行モード」チェックボックス。ユーザーの改行位置で2行分割・中央揃え。
- localStorage で保存/復元、「既定値に保存」「リセット」を用意する(汎用 `Store` ヘルパ)。

## 4.6 モーダルの設計パターン(v=427/428 draftPostModal から確定)

複数回の改修で定まったモーダルの構造と部品。次のモーダル追加時はこれに揃える。

**構造:**
- オーバーレイ: `position:fixed; inset:0; z-index:9999; background:rgba(0,0,0,0.82); overflow-y:auto`(長い中身もスクロール可)
- カード: `background:#0e1422; border:1px solid #2a3346; border-radius:14px; overflow:hidden`(内側 div の `box-sizing:border-box` も必須=縦潰れ防止)
- ヘッダー: `padding:13px 16px; border-bottom:1px solid #1e2d42; display:flex; justify-content:space-between; align-items:center`
  - 左=タイトル(`color:#2bb3c0` ティール・`.95rem` `font-weight:700`)
  - 右=**✕ 閉じるボタン**(`background:none; border:none; color:#7a8fa3; font-size:1.2rem; padding:2px 8px`)
  - **★閉じるはヘッダー右**に置く。フッターには置かない(v=428 Chami指示で移動した確定パターン)
- ボディ: `padding:16px 16px 20px`

**セクション区切り:**
- ラベル: `font-size:.72rem; font-weight:700; color:#9fb0c3; letter-spacing:.06em; text-transform:uppercase`
- 水平 divider: `height:1px; background:#1e2d42; margin:18px 0`

**インライン「コピー」ボタン(input/textarea の右隣):**
- `padding:7px 12px; font-size:.78rem; border-radius:7px; border:1px solid #3a4a5e; background:#0e1a2b; color:#aabbc8`
- input/textarea と `display:flex; gap:7px; align-items:flex-start` で並べる

**完了/主要アクション:**
- モーダル最下部に**全幅ボタン**(1つ): `width:100%; margin-top:20px; padding:13px; border-radius:10px; border:none; background:#2bb3c0; color:#04222a; font-size:.95rem; font-weight:700`

**悪い例(v=427→v=428 で直された):**

### ★ C-005 端末設計前提(2026-07-22 Chami確定・裁定A/C-005 登録済み)

> **投稿導線はスマホ1台で完結する。端末をまたぐ前提の設計をしない。**

**根拠(固い構造的制約・気分で変わらない):**
- YouTube Shortsで許諾音楽を付けられるのはスマホアプリからのみ(著作権許諾経路の制約)。
- 動画生成→投稿完了まで一連の流れ。途中で端末を変えるメリットがない。
- よって「スマホ前提」は設計の確定前提として使ってよい。

**★ 適用外(取り違え禁止):**
- **「書き込み」=スマホ1台で完結してよい**。
- **「表示(履歴閲覧)」=全端末で見えなければならない**。これは別の話。
  - `displayItems_()` のシート補完は**維持**。落とさない・弱めない。
  - シートを正本にする意味=「どの端末から見ても履歴が見える」こと(INC-112 の再発防止)。
  - 「端末をまたがないなら表示も端末ローカルで足りる」は**誤読**。

**実装に転換する時のチェック:**
1. 書き込み経路か表示経路かを最初に区別する。
2. シート補完(`displayItems_()`)を弱める変更は C-005 では正当化されない。

## 5.9 承認プロセス(C-006 発効済み・2026-07-22)

> **フロントのpushは承認不要で実行してよい。(裁定 C-006)**
> Chami原文:「なんならプッシュデプロイまで済ませておいてほしい」

**承認不要で実行できる作業:**
- 読み取り・影響範囲の測定
- 部門間の連絡と報告(send message / dispatch / 返信)
- `docs/` 配下の下書き
- **フロントのpush**
- GAS/Workerのデプロイ

**★適用外(今まで通り上申する):**
- **削除**(裁定 C-003。ファイル・行問わず消さない。退避は可)
- 本番データの書き換え・移行
- 設定変更(権限・トリガー・シークレット・registry)
- **既存の挙動を変える実装**(「改善は承認制」の網は生きている)

**★誤読防止:**
「pushは承認不要」 = 承認済みの変更を出すのに**もう一度承認を取りに来るな**という裁定。
**新機能を勝手に作って出す許可ではない**(C-001 と「改善は承認制」が引き続き縛る)。

**★link-worker に注意:**
`link-worker/**` のpushはGitHub Actionsで**自動デプロイ** = **pushした瞬間に本番**。特に慎重に。

**★?v=バンプ:**
`?v=` は必ず `node scripts/bump.mjs` で一括。手で個別に上げるとCIスモークが即赤になる。

## 5.95 ★Claude/Anthropicデザインから得たヒント(2026-07-28 Chami依頼で調査)

> Chamiの懸念=「配色・ボタン配置がワンパターン」。Claude/Anthropic公式のUIを調査して抽出した改善ヒント。
> ★**2026-07-28 Chami承認済み: ヒント①〜④全部を draftPostModal(投稿モードモーダル)に試験適用する。**
> 結果を見て気に入ったものを「確立済み」へ昇格させること。

### 根本原因(なぜワンパターンに見えるか)
**現状**: `#0e1422`(冷たい青黒) + `#2bb3c0`(ティール1色) + 均一な暗いカード
**Claude/Anthropicが持っていて我々が無いもの**: 暖色・サーフェス階層・アクセントの多様性

### ヒント①: 暖色方向へのシフト(最重要)
Claude/Anthropicは**暖色系のダーク**を使う(青み無し→茶系の黒)。
我々の`#0e1422`は「青みを帯びた冷たいダーク」=ロボット感・一色感の主因。

| 用途 | 現在 | 暖色代替案(参考) |
|---|---|---|
| ベース背景 | `#0e1422`(青黒) | `#12100e`(暖黒) 等 |
| カード面 | 均一 | `#1c1916`(暖ダーク) 等 |
| テキスト | 白系 | `#ede8df`(クリーム) 等 |

★値は参考例。採用するなら実機確認後にChamiへ提案→承認→確定の順。

### ヒント②: サーフェス階層(3段)
同じ暗さのカードが並ぶとのっぺりする。
**3段の微妙な明度差**でUIに奥行きが出る:
1. 背景(一番暗) → 2. カード → 3. 浮いた要素(モーダル/ドロップダウン)

### ヒント③: アクセントに暖色1本追加
現在はティール1色のみ。**警告・プレミアム・強調**に暖色アクセント(アンバー系 `#e07a4a` 等)を1本加えると、印象が変わる。
★無理に変える必要はない。**新しい要素を作る時だけ選択肢として持つ**イメージ。

### ヒント④: タイポグラフィのコントラスト
Claude系UIは**見出しを極端に太く(800)、本文を軽く(400)** する。色を変えなくても視覚的リズムが生まれる。
→ h1/h2: `font-weight:800` / body: `font-weight:400` / label: `font-weight:600`

### ★「指示しないと反映されない」問題の本当の解決策
クオリティが上がらない本質は「KBが育っていない」こと。
- **型①** Chamiが直したら → このファイルへ即追記
- **型②** UIが通ったら → §4.5 実装確定表へ昇格

今日の調査で §4.5 の未確定7→2件に減らした。これを続けるのが根治。
