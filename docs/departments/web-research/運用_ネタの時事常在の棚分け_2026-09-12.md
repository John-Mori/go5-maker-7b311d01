## 何を使うか(道具)

- `scripts/neta_shelf.py` — 集めたネタに棚の札を付ける**後処理の別道具**。
  取得3本(`scrape_5ch.py` / `scrape_matome.py` / `matome_distill.py`)には触れない=既に在る出力
  (`distilled/*.txt` のヘッダ + `matome_*.jsonl` の `fetched_at`)を読むだけ。
  ★第一版は今在る値だけで回す。取得側の改修はしない(正本メモ §境界)。

## 毎日の手順

1. その日の収集(5ch/まとめ一覧/蒸留)が回った後に走らせる:

   ```
   python scripts/neta_shelf.py --date <YYYY-MM-DD>
   ```

   - 出力台帳= `local/_work/neta_shelf_<date>.jsonl`(1行=1件・棚の札 `shelf` と失効時刻 `expire_at`)。
   - 標準出力に**内訳**が出る(下記)。
2. 内訳の3行を見る。歩留まりが薄い時、その正体がどれかを読む:
   - **旬で死んだ分**(時事×失効済み)= 取得が遅い/頻度が足りない。→ 打ち手は**取得の頻度・速さ**。
   - **玉が無い分**(常在×バー未満)= そのソースに玉が乏しい。→ 打ち手は**ソース選定**(論争・流行語の濃い板/まとめへ寄せる)。
   - **時事だが未失効でまだ薄い**= 今から拾えば間に合う。→ その場で蒸留に回す候補。
3. 出す順(正本メモ §並べ方):
   - 時事棚= **失効が近い順**(先に死ぬものを先に)。同着は `comment_count` 多い順。
   - 常在棚= 急がないので**質(コメント多い順)**。渡す時は方策C(同一バッチで題材を固めない)に従う。

## 判定の要点(実装が正本メモのどこを写しているか)

- 主判定= **タイトル文字列**(正本メモ §基準 材料1)。具体日付 / 告知・速報語 / お気持ち・炎上語 → 時事。
- 失効= 具体日付は**その日付の翌0時**、告知・炎上は **`fetched_at`+72時間(暫定)**。
- `ikioi` / `tags.topic・box` は**補助のみ**(`_tagged` は1ファイル1レコードしか無い実測=主判定に使わない)。
- **fail-open= 材料が足りなければ捨てず常在棚へ落とす**(時事で取りこぼすより常設で拾って後から上げる)。
- ★基準の語彙・閾値を**当室で勝手に動かさない**。動かすのは正本メモの版を上げてから(`neta_shelf.py` の `CRITERIA_REV` を同時に写す)。
  誤爆・取りこぼしに気付いたら**較正の材料として ad研究室へ1行**返す(下記較正条件)。

## 較正条件(この運用と基準の版を上げる引き金・正本メモ §較正条件)

- 棚を付けたネタが**20件**たまった時、または「時事棚のまま失効させた(=旬に間に合わなかった)」が
  **3件**出た時のいずれか早い方で見直す。
- 見直しの時に **72時間 / 翌0時の2つの暫定値を実測へ差し替える**(基準の差し替えは ad研究室、当室は実測値を供給する)。
- 現時点の観測(2026-09-12 初回・distilled 6件/累計40件): 薄い蒸留の正体は **玉が無い分が支配的**
  (常在×薄い 35件 / 旬で死んだ 0件)。= 歩留まりの薄さは取得頻度ではなく**ソース選定の問題**。
  打ち手= 論争・流行語の濃いソースを足す/優先する(parse は実測で正常=触らない)。
