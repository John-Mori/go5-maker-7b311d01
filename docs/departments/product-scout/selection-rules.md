## E直行ゲート (スコアリング前に判定・1つでも該当なら見送り)
スコアリングより先に判定して評価コストを削る。1つでも該当したら素材・採算スコアを付けずにEとする。
- G1: 電車内基準(電車内で見られて困らないコマだけ使う)を満たすコマが3枚未満。1コマ目・サムネは必ず基準内でなければならない(CLAUDE.md §6.1)。
- G2: 同一作品が対象chで使用済み。acc1とacc2間の同一作品は原則回避する。コマ・文言を必ず変える条件つきでのみ可。
- G3: 5秒で意味が伝わる素材が無い(persona_detail §5-E)。
- G4: 無料流通が広範で購入動機が崩れている。

## 素材スコア (星南・5点満点)
1つでもゲート該当なら採点しない。各項目の最大点を超えない。
- 停止力: 1コマ目が0.5秒で目を止めるか。0-2点。
- 未解決の疑問を作れるか。0-1点。
- 基準クリア素材量: 4-5枚=0.5点・6枚以上=1点。0-1点。
- 差分・違和感の見えやすさ。0-1点。

## ★1コマ目素材の最重要基準 (SA-H007・2026-08-05 分析部門三笘さん→当部門)
正本= docs/departments/shorts-analyst/3部門共有_1コマ目知見と展開.md §1・1コマ目視覚特徴_統合分析.md。全て自社実測(n=14)。
- **1コマ目は「0.5秒で読めるか」が全て**=素材スコア「停止力」の判定軸をここへ寄せる。**多コマ密で読めない1コマ目は5本全滅(wv=3・例外ゼロ)**=多コマ密でしか語れない作品は後回し(採点で停止力0-1に留める)。
- **当たりの型**: カラー×大コマ1〜2枚×絵だけで意外な状況が完結(ボタンパネル/名簿×グリッド/ビフォーアフター/表情の落差)。この型のサンプル画像を持つ作品を優先。カラー中央値wv1710 vs モノクロ3。
- **露出示唆は再生と無関係**=露出で釣らない。むしろ佐藤空氏知見(露出下げ6本中5本がフィード通過)+P0電車内基準を素で満たすサンプルがある作品を選ぶ(再生の主因は可読性であって露出ではない)。
- ★**この判定にはサンプル画像の目視が要る**=D1の数値だけでは確定できない(info_jsonにsample無し/当部門は画像を直接見られない)。1コマ目型・露出はChami提供のサンプルURL or 画確認後に確定する。数値で出せるのは採算予選まで。

## 採算スコア (クラウディア・5点満点)
割引率は非累積(50%以上は2点で確定・1点と足さない)。
- 割引率: 30%以上=1点・50%以上=2点。0-2点。
- 販売数sales_n。0-1点。
- レビュー: 件数×平均で評価。0-1点。
- 今出す理由: セール期限・新作鮮度。0-1点。

## 判定表
| 判定 | 条件 |
|---|---|
| A(即制作) | ゲート全通過+素材4以上+採算3以上 |
| B(限定テスト) | 素材4以上+採算1-2(集客テスト) / 素材3+採算4以上 / 二人の意見が割れた時(小規模テストへ・persona_detail §5-B) |
| C(セール待ち) | 弱点が価格・時期だけで、セール到来で解ける |
| D(素材保存) | 素材2-3で構図・訴求の参考価値あり |
| E(見送り) | ゲート該当 or 素材0-1 |

## 注記
- 成約数は構造的に観測不可。採算はクリック誘発力・市場の強さ(販売数・レビュー)で語る。
- 「用途: 集客型/成約型」の分類は維持する。ただし成約数を根拠にしない。

## 競合・伸びの解釈の落とし穴 (2026-08-02 AD研究室モドリッチ→当部門・分析部門三笘さんの統計手法より)
正本= docs/departments/shorts-analyst/競合分析_統計手法.md §0・§2・§4。
- **競合の総再生数はチャンネル規模で3桁ぶれる**(実測レンジ 751〜695,883)。登録者数×総再生数 Spearman ρ=+0.45=大手chは全動画が底上げされる。
- **再生数の生の順位だけで「伸びた/伸びてない」を判断しない**(規模の交絡に騙される)。伸びの比較は必ず**同じch内・同規模帯**で行う。ch跨ぎの生順位でTOP/ワーストを語らない。
- 現データは速度上位200固定=非ランダム標本。ここでの「ワースト」はこの母集団内で相対的に伸び切らなかった動画であって、chの絶対的な底ではない。
- 当部門への効き: 競合作品を「動画化の当たり」として引く時、生再生数の高さだけで強い題材と判断しない。規模を揃えた上での伸び・停止力・素材価値で見る。

## 打席数×多様性の確保 (方策C・2026-08-05 AD研究室モドリッチ→当部門・分析部門三笘さんの投稿振り返りより)
正本= docs/departments/shorts-analyst/投稿振り返りと方策_事業部共有.md §2C・§4。
根拠= ヒット集中構造(SA-H002)。1本の完成度を上げるより、本数を出して当たりを引く方が期待値が高い。実測=8/1に週再生4,424・1,504のヒット、8/2〜8/4の5本は週再生1〜3で不発=振れ幅が全て。→ **12本/日(6×2ch)の全採用方針は、少数を磨くのでなく多様な打席を並べる方針で正しい。**
- **同一バッチで題材を固めない。** 1日の候補群(最大12本ぶん)で、同じジャンル・題材が半分を超えないよう散らす。少なくとも3系統以上の異なる題材を並べる(例=逆NTR/男性受けOL・学園・聖女… を混ぜる。全部同系統で埋めない)。
- **散らす軸は3つ**: ①題材/ジャンル ②コマ構図・画風 ③訴求軸(意外な結末・ギャップ・関係性の反転…)。この3軸が前バッチと丸かぶりしないよう1件ずつ確認する。
- **★打席の"質"のガードは1つだけ**: 曖昧フック(方策A=隠し問い型「どう〜?」「〜と思う?」で結末を隠す題材)へ寄る候補は多様性の名目でも入れない。実測でこの型は最大10再生・1本もブレイクしていない。散らすのは題材であって、当たらない型を混ぜることではない。
- **acc1/acc2の重複回避(E直行ゲートG2)と両立させる。** 2ch分を埋める時こそ題材が被りやすい=多様性チェックが重複投稿リスクの一次防波堤も兼ねる。
- 当部門の運用: Packet報告時に「多様性メモ」1行=前バッチと題材/訴求軸がどう違うかを添える。同系統に偏った日は理由を書く。

## 集客型/成約型の分類基準 (2026-07-28 okadaさん実績コンサル情報より追加)

出典: 実績コンサル情報.md / okadaさん(月92万円実績・2026-06-12)。
Packet の「用途」欄へこの基準で記入する。複合要素がある場合は判定理由を1行添える。

**成約型 (購入に繋がる・再生は伸びにくい)**
- 価格が低い(目安: 通常価格1,000円以下)
- 実売数が多い=既に人気のジャンル・特定層に刺さっている
- 購入障壁が低く、クリック後の離脱が少ないと推定できる

**集客型 (再生が伸びやすい・チャンネルパワーを底上げ)**
- 1コマ目の停止力が高い(素材スコアの停止力項が2点)
- 親しみやすい画風・万人に引っかかるビジュアル
- 実売は控えめでも画としての強さが突出している

**ポートフォリオ目安 (okadaさん1日8本ベース)**
- 成約型: 3〜4本 / 集客型: 4〜5本
- どちらを厚くするかは shorts-analyst の「勝ち型上位6本の分類結果」で調整する

## 定期スキャン (裁定4・2026-07-18 Chami承認「ちゃんと毎朝欲しい」)
- 頻度: **毎日・朝に1回**。朝を逃した日(閉窓等)は、その日最初の起床時に**必ず遅延実行**する(遅れても抜かさない)。
- 母集団の定義(2026-07-18実測): D1 go5_fanza worksの実体=①Chamiの追跡サークル(tracked_makers・現在2件=千暮ゆき/アビィロード)の作品の実売追跡(PC側が3時間ごと自動取得) ②Chamiが候補タブへ追加した作品の詳細(価格・サンプル画像)。**市場全体の新作は含まれない**。母集団を広げる手段=追跡サークルの追加(アプリ操作のみ)or市場巡回の新設(改修案件)。
- 恒久化(2026-07-18実装): 毎朝の自動配信スクリプト `scripts/product_scout/morning_scan.py`(採算速報を窓非依存で投稿)。当日のmarket_snapshotをSELECT→採算予選(下記)→通過1件以上ならクラウディア名義でこの部屋へ自動投稿・ゼロなら沈黙。冪等マーカー=`local/product_scout_morning_last.txt`(同日二重投稿しない)。`--dry-run`で投稿せず確認可。Windowsタスク登録=`register_morning_scan_task.ps1`(毎日06:10・Worker cron06:00の10分後)。素材A-E判定は窓が開いた時の二段目。
- 手順: works表から発売90日以内をsales_n降順で読む→使用済み台帳と照合(E直行ゲートG2)→採算スコアで予選→通過した上位最大3件を「採算予選通過・素材確認待ち」として部門chへ提案(クラウディア名義)
- 予選通過ゼロの日は**提案を出さない**(ノイズゼロ)。
- 制約: セール期限・レビューはD1に無い=提案時に「追加確認事項」として明記。素材スコアはサンプル画像(info_json内のsampleImageURL)の確認後に確定し、A-E最終判定は素材+採算が揃ってから。
- この窓が開いている日に限る(閉窓日は飛ぶ)。ただし**市場スナップショットの取得自体はWorker cronが毎朝自動実行**(2026-07-18稼働)=窓が閉じていてもデータは溜まる。窓が開いた時に読んで提案する。
- 市場側の予選: market_snapshotから「レビュー件数×平均が強い(例 件数30以上×平均4.4以上)」「高割引(40%以上)」「rank上位」で予選。採算スコアに乗せる。閾値は暫定=較正対象。
- 市場予選通過top3は実売取得キューへ自動投入(Worker巡回内・2026-07-18)=翌サイクルでsales_nが埋まる。ただしsales_nは即時ではない(投入日は空欄で提案し得る)。
- ★セール期限はDMM APIで取得不可(2026-07-18実測=campaignフィールド無し)。市場作品の提案でも期限は「出品ページで要確認」を付す。

- 判定表・スコアは素の箇条書きで示す。キャラ口調の演出を混ぜない。

### 投稿おすすめ様式 (★ゴラッソ 2026-08-06・8/05と8/06の投稿にChamiがゴラッソ=この形を繰り返す)
なぜ良かったか=**列挙で終わらせず「Chamiがそのまま動ける形」にした**から。次も同じ質で出すための再現手順:
1. **各作品に「狙い」を必ず1語付ける**(成約寄り/集客寄り)+**一語根拠**(例「超多販売×低価格」「rank最上位」)。データの羅列にしない=1件ごとに"何のために出したか"を言い切る。Chamiは番号で選ぶので、選べる形で出す。
2. **一貫スキーマで密に並べる**=`cid / 価格 / 割引 / rc・評価 / rank / 狙い`。全項目が採否の入力。太字で本命を立てる。
3. **ポートフォリオを設計して添える**=成約:集客の**配分**(例 4:2)+**題材分散**(店長/家族/回春/学園…)。分散はCLAUDE.md §6.1のinauthentic/2ch重複回避に紐付く=飾りでなく制約由来。
4. **できない部分を正直に名指す**=素材の型(1コマ目構図・露出可否)は当部門は画目視が要り確定不可。**なぜ不可か**(D1に画像が無い/画そのものを見られない)+**最も安い次の一手**(気になる数本のサンプルURLを貼れば型判定する)を添える。ごまかさない・省かない=これが信頼の核。
5. **数字は全部その場で測る**(market_snapshotをSELECT)。記憶の数字を再利用しない(§1)。
6. **「候補内/候補外」の二系統要求には分けて出す**(8/06追加)=【A】全候補から強い順+【B】候補に入れてない売れ筋。候補外はpool未登録でrank/rc上位のものをmarket_snapshotから拾う。

## データ取得手順
- D1 go5_fanza(読み取りのみ): fanza-workerディレクトリで `npx wrangler d1 execute go5_fanza --remote --json --command "SELECT ..."` を実行する。SELECT(読み取り)のみとする。
- **市場全体(market_snapshot・2026-07-18 稼働開始)**: 毎朝のWorker cronが同人フロアの rank上位100+新着100 を保存(設計書=設計書_市場全体巡回_2026-07-18.md)。**レビュー件数(review_count)・平均(review_avg)が取れる**(Chami由来のworks表には無い)。当日分の読み方: `SELECT cid,title,price,list_price,discount_pct,review_count,review_avg,rank FROM market_snapshot WHERE day=<当日JST> ...`。掃除=90日。sales_n(実売)はこの表に無い=予選通過分のみworks側で補完。
- cand_items(候補タブのlocalStorage)はBashから読めない。エクスポート手段の有無はsystem-engineerへ要件として引き継ぎ中(未確立)。
- FANZAページのWebFetch可否(年齢ゲート)は未検証。初回の評価依頼時に1回試し、結果をfindings.mdへ記録する。
- 競合状況・無料流通の調べ方は未定義。当面はChami提供情報+検索で埋め、手順が確立し次第この節へ追記する。
