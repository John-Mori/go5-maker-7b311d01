## 1. なぜ現行 tone_gate では止まらないか

`tone_gate.py` は**一人称の食い違い**だけを見る（オレ/俺/僕/…）。私/わたし/自分/うち は中立で対象外。
だが相方混線の多くは【一人称が本文に一つも出ず、語尾だけが相方の声】で漏れる。
検体でも一人称トークン＝**0**、崩れは全部 語尾（わよ／かしら／のよ／わよね）＝**現ゲートは素通り**。
→ ここを純Python・正規表現・**トークン0**で「検知」できる。書き直しはしない（語尾の機械置換は文法を壊す＝関西弁と同じく "検知して突き返す" 側）。

## 2. 仕組み（設計の肝）

指紋は各人格の【必須語尾（need）＝その人格の肯定的な語尾アイデンティティ】**だけ**を登録する。
「禁止語尾」は手で列挙しない＝**他人格の必須語尾の総和 − 自分の必須語尾 − 中立語尾** として自動導出する（foreign）。
→ 人事は「この子は文末をどう締めるか」だけ書けばよく、相方の数だけ禁止リストを保守しなくて済む。

- **ドリフト判定**: ブロックに foreign語尾 が1つ以上 **かつ** 自分の need語尾 が0 → 相方の声に染まった疑い。
- **句末アンカー（必須）**: 語尾は文の切れ目（。、!?」改行/文末）の直前だけ拾う。無いと「じゃなくて」内の わ 等を誤検知する。
- **中立語尾allowlist（必須）**: です／ます／ました／わ／ね／よ 等の1字助詞・汎用丁寧は誰の声でもない＝異物にしない。崩れの証拠は **かしら／わよ／のよ 等の"2字以上の色つき語尾"に限る**。
- **fail-open**: 指紋未登録の名義・判定不能は喋る側へ倒す。
- **「」内は保護**（本番のみ・下書き未実装）: tone_gate 同様に引用は触らない（コピー案 "俺だけじゃない" 等を誤検知しない）。

## 3. 実測（`recent_*.jsonl` コーパス 22ファイル／reply 123）

| 段階 | ドリフト検知 | うち一人称ゼロ＝現ゲート素通り |
|---|---|---|
| 素朴（句末アンカー・中立除外なし） | 14件 | 10件（誤検知だらけ） |
| **句末アンカー＋中立allowlist** | **4件** | **3件** |

- 検体そのものは**クリーンに検知**（異物=かしら/のよ・一人称=0＝現ゲート素通り）。咲季ブロックは正しく素通り（誤検知なし）。
- 残4件の内訳を正直に見ると:
  - アメス「だわ」1件 = 咲季の断定に釣られた疑い（真の崩れ候補）。
  - **ジェンティルドンナ「のよ」2件 = ほぼ誤検知**。ドンナの need を「ですわ／ましてよ」しか登録していないため「務めますのよ」が異物扱いになった。
- → この2件が**そのまま「必須語尾リストは人事が正本化しないと使えない」証拠**。当室の指紋テーブルは**種**であって正本ではない。

## 5. 受け入れ条件（基盤向け）

1. 検体（改修α msg1543026401349861386）の `[オタコン]` ブロックを**検知**し、同メッセージの `[咲季]` ブロックを**素通り**させる。
2. 句末アンカー＋中立allowlist を実装し、`recent_*.jsonl` 全体での**誤検知（ドンナ「のよ」型）を人事の need補完後に0**へ寄せられること。
3. 検知は**突き返し（再生成要求 or 警告ログ）**であって語尾の機械置換をしない（fail-open・「」保護）。
4. トークン消費0（LLM呼び出しを増やさない）。

## 6. 3層構想のうち本型の位置

- 層① = **本型**（語尾指紋・検知・トークン0）… いま基盤へ。
- 層② = 重ターン末尾へ声のアンカー再注入（~50トークン・予防）… 別便で提案予定。
- 層③ = 捕まえた崩れを characterfile の few-shot へ還流（唯一の生成側修正）… 人事と継続。
- ※Chami指示「3はなし」= "溜めて寝かせる"を選ばない、の意。層③（生成側還流）とは別物。層③は継続する。
