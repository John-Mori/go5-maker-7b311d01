## 何を止めるか(1行)
**常駐(デーモン)を「足す/退役させる/読むファイルを変える」時に、①コードの載せ替え経路 ②その脈を見ている監視 の2つを同じ作業で決めないと、「入れたのに効かない」「退役したのに監視だけ生き残って誤警報」が繰り返し出る。** 常駐は"置いた瞬間に動く"物ではない——載せ替える機構と、生死を見る機構に、別々に登録して初めて運用に乗る。

## 不変条件(守れているか作業前に見る)
- **I1 載せ替え経路を必ず指名する。** 常駐は載せ替え機構が**2つあり対象が排他**([[daemon-reload-two-mechanisms]])=
  - **dept_daemon 系 → `daemon_keeper.WATCH_FILES`**(daemon_keeper.py:170-179。import閉包9本＝session_relay/prompt_spill/session_rooms/tone_gate/naming_gate/leasequeue/session_presence/persona_send/dept_names)。RELOAD_DEBOUNCE_SEC=90。
  - **常駐7本(absence_watchdog/local_responder/gemini_responder 等)→ `supervise_daemons.ps1` の codever比較**(控え=`local/_daemon_codever/<name>.txt` と閉包sha1・`$codeMinAgeSec=600`)。
  - ★新しく常駐が**読むファイル**を足したら、それが上記どちらの WATCH_FILES/閉包に入るかを**同じコミットで**足す(C-042)。入れ忘れると「編集したのに古いコードが走り続ける」。
- **I2 監視の登録・抹消を載せ替えと対で行う。** 常駐を**足したら**その脈を見る監視(`deadman_check.py` の EXPECTED 等)へ**追加**し、**退役させたら**その監視から**抹消**する(C-044)。片方だけ触ると「死んだ常駐を待つ誤警報」か「見張られない盲点」になる。
- **I3 監視の読み手を全数数える。** 1つの常駐の生死を見ているセンサーは1つとは限らない(警報・鮮度番犬・自己参照check)。退役/改名の前に**そのセンサーの読み手を grep で全数**出し、全部を同時に更新する(C-044 の原文)。
- **I4 復活/警報は本番条件を1回通してから「配線済み」と言う。** 登録しただけ・ソース文字列一致だけでは「動く」証拠にならない([[never-fired-never-verified]]・共通規律§3)。入力を差し替えて分岐を実行で通す。

## 機械で止める案(プラットフォームSE/イージス研究室へ渡す検査の下書き)
改修α側のCI門3兄弟(check_ui_ios.mjs 等)と同じ**ベースライン凍結方式**を、基盤側(常駐の起動スクリプト群)に置く:
```bash
# 1) 常駐の名簿(DEPT_CONF/supervise対象/keeper WATCH_FILES)を単一の真値表へ集約し、
#    「起動される常駐」の集合を出す。
# 2) その各名が (a)載せ替え機構=keeper WATCH_FILES か supervise codever のどちらかに居る
#    (b)監視=deadman_check.py EXPECTED 等に居る —— の両方を満たすかを assert。
# 3) 名簿から消えた名が、監視側にだけ残っていたら赤(退役し忘れの誤警報の芽・C-044)。
# 4) 常駐が新規に読むファイルが、その常駐の載せ替え閉包に入っているかを assert(C-042)。
```
検査の芯= **「常駐の集合・載せ替えの集合・監視の集合の3つが一致しているか」**。ずれ=登録漏れ or 退役し忘れ。既存の一致はホワイトリスト=回帰ゼロ。

## 直し方の定型(常駐を触る人がやること)
1. **足す時**= 起動名簿に足す → 載せ替え機構(keeper WATCH_FILES / supervise codever のどちらか)に足す → 監視(deadman EXPECTED 等)に足す → 復活を本番条件で1回通す。**4つ揃って「配線済み」**。
2. **退役させる時**= 起動名簿から外す → 監視から**抹消**(読み手を grep で全数) → 載せ替え控えを掃除。**監視だけ残すと誤警報**(C-044)。
3. **読むものを変える時**= 変えたファイルが載せ替え閉包に入っているか確認(C-042)。
