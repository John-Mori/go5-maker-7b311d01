## 何を止めるか(1行)
**要素セレクタ(`button{...}` `input{...}` 等)や `[hidden]` へ far-reaching なプロパティを書くと、後から足す部品(モーダル/オーバーレイ/ツールバー)が黙って継いで壊れる。** 部品ごとに個別で打ち消す運用は、部品を足すたびに再発する。

## 実測した再発(=この型が要る証拠)
- **グローバル `button{width:100%}` の波及**= style.css で **3箇所が個別に後追い**で打ち消している:
  - `130` `.promo-toggle{... width:fit-content}`(トグルが全幅化)
  - `137` コメント「★恒久対策(ボタンが無駄に横伸び)：グローバル button{width:100%} を継いで全幅になっていた」
  - `518-520` `.fz-modal button,.vedit-modal button{width:max-content}`(モーダルのボタンを打ち消し)
  → 新しくボタンを持つ部品を足すたび、**気づくまで全幅で出て🔥→個別に width を当てる**の繰り返し。
- **`[hidden]`×`display:flex` の波及**(インシデント.md INC-37/47)= オーバーレイに `display:flex` を書くと UAの `[hidden]{display:none}` に勝ち、`el.hidden=true` でも**見えない板がタップを奪う**。**4日で2度**(06-25 ウィザード / 06-29 編集モーダル)。同記録が「全称スタイルの波及」と名指し。

## 不変条件(守れているか機械で見る)
- **I1**: far-reaching なプロパティ(`width` `display` `position` `margin`)を**裸の要素セレクタ**(`^button{` `^input{` `^a{` 等)や `[hidden]{...}` に書かない。書くなら**器のクラスへスコープする**(`.form button{...}`)。
- **I2**: `button`/`input` を含む**新しい部品**(モーダル/オーバーレイ/カード/ツールバー)を足したら、その部品のボタン幅を**明示する**(`width:fit-content|max-content|auto`)か、器が I1 を満たすスコープ下に入れる。
- **I3**: オーバーレイ(`hidden` で開閉する板)は `display:flex` 等を書いたら **`.部品[hidden]{display:none!important}` をセットで**書く(INC-37/47 の定型)。

## 機械で止める案(改修αへ渡す検査の下書き)
ビルド無しの素CSSなので **grep 1本の作成時プリフライト**で足りる(CIのスモークへ相乗り可):
```bash
# NG候補= 裸の要素セレクタに far-reaching プロパティ
grep -nE '^\s*(button|input|a|img|ul|li)\s*\{[^}]*(width|display|position|margin)' style.css
# NG候補= flex を書いたオーバーレイで [hidden] の打ち消しが無い部品
#   → 部品名を拾い、同名の "[hidden]{display:none" が在るかを対で確認する小スクリプトにする
```
検査の芯= **「裸の要素セレクタに far-reaching プロパティが1つでも増えたら赤」**。既存の裸ルールはホワイトリストに退避し、**新規追加だけを弾く**(save-path型と同じ「新規の混入を止める」思想。既存は据え置き=回帰ゼロ)。

## 直し方の定型(部品を足す人がやること)
1. 新しいボタンを持つ部品を書いたら、**ボタン幅を明示**する(`width:fit-content` 等)。
2. オーバーレイなら `.名前[hidden]{display:none!important}` を**同じコミットで**書く。
3. グローバルの裸ルールを増やしたくなったら、**器のクラスへスコープ**してから足す。
