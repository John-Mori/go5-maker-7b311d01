# 改悪(`改悪`)スタンプ — 変更起因の後退(regression)

## 1. Chamiの言葉(実物・2026-08-23 msg 1541111145086197770)
> 改悪スタンプを作った。意図としては以前は問題なく機能していたものが、システムや作りがちょっと
> 変わったために以前と同じ挙動ができなくなったことを指すもの。これは他と違ってすぐ認識して欲しい
> +翌日に再発などと同じように振り返って欲しい内容。

絵文字 = `<:kaiaku:1541110670748156014>`。

## 2. 何を指すか(=既存3枚との線引き)
| 印 | 合図 | 数える鍵 |
|---|---|---|
| 🔥 炎上 | 重大インシデント。恒久対策しろ | 恒久対策の有無 |
| 再発 saihatsu | 同じ**依頼**を何回も言わせた | 何度目か(Z1) |
| ゴラッソ golazo | 要望より良い物が出た | 良かった型(横展開) |
| ★**改悪 kaiaku** | **前は動いていたのに、変更(commit/リファクタ/仕様変更)のせいで挙動が消えた=後退** | **どの変更が壊したか＋回帰ガードの有無** |

- ★**再発とは別物**。再発=「同じお願いの繰り返し」、改悪=「前は出来ていた事が変更で消えた」。**Z1へは数えない**(別枠=変更起因の後退という独立の真因クラス)。
- ★**扱いの二本立て**(Chami指定): ①**すぐ認識**(他と違い翌朝を待たない) ②**翌日に振り返り**(再発と同じ土俵で巡回に載せる)。

## 3. 分析上の扱い(この部門のPDCA)
- **1件=1リグレッション**として追う。周回集計の鍵は「**どの変更が後退を入れたか**」を実物で1件ずつ紐づけること(commit/リファクタ名まで)。
- **恒久対策=回帰ガード**。改悪の締めは「気をつける」ではなく「**同じ種類の変更でまた黙って壊れたら赤くなる検査**」(C-038・C-053)。回帰ガードの無い改悪は同じ変更で再発する=**開いたまま数え続ける**。
- 週次KPI= 「改悪の件数」と「**回帰ガードが入っていない改悪の件数**」を分けて出す(🔥の「恒久未達件数」と同じ思想)。

## 4. 機構(どう載せたか)
- `scripts/discord/reaction_watch.py`(毎朝8時のスタンプ巡回・タスクスケジューラで新規起動=常駐でない=載せ替え不要)へ **kind=`kaiaku`** を追記(追記のみ・commit で後述):
  WATCH / KIND_ORDER(炎上の次=即認識) / ORDERS / HEADING / KAIZEN_SECTION / WHY。
- 回帰ガード= `scripts/discord/test_enjo_stack.py` §9 に「WATCHの全kindが ORDERS/HEADING/KAIZEN_SECTION に揃っている」構造検査を追加(28/28 PASS・辞書を1つ忘れると赤=改悪自身の回帰ガード)。
- ★**「すぐ認識」は8時巡回だけでは叶わない**(実時間の検知が要る)=そこは基盤の領分。§3.9でHQへ渡し、①裁定化(全部屋が注入プロンプトで即認識) ②実時間検知の要否を基盤へ、を上げた。

## 5. 残(open)
- 実時間検知(intraday)の実装可否= 基盤(プラットフォームSE/イージス研究室)の判断待ち。
- 翌朝8時の本番巡回で改悪が実際に拾われることの実物確認= 次に改悪が付いた翌朝に §4.55 で確認するまで「入れた(確認待ち)」。
