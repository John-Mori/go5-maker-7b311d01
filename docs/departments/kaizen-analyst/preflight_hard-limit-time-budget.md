## 何を止めるか(1行)
**GASの1実行≈6分・cron間隔のような"硬い上限"の下で、シート行数・URL数・予約数に比例して伸びるループ(特に1件ごとに `Utilities.sleep()` を挟むもの)を、時間予算(`Date.now()-t0` で打ち切る枠)無しで回すと、データが増えたある日"たまに遅い"ではなく"全実行が時間切れ→Googleがトリガーを自動停止→静かに全滅"になる。** 打ち切りが無いループは、伸びた瞬間に「毎回失敗」へ相転移する。

## 実測した再発と"今まさに残っている穴"(=この型が要る証拠)
- **INC-116**(2026-08-16)= `snapshotStats` が①投稿日時バックフィル(全履歴行を走査しsetValue)②全コードのクリック取得(1コードずつ+80ms待機)で膨らみ、履歴増で**6分超→Google自動停止→ピーク記録が全滅**。対策は「重いループを時間予算で頭打ち」(`RUN_T0`＋`BUDGET_DATEFIX_MS`/`BUDGET_CLICKS_MS`/`BUDGET_RECS_MS`)。**コメントに自分で「★心がけでなく機構で6分を超えさせない」と書いてある。**
- ★**しかしこの判断は `snapshotStats` 1箇所だけに入った。同じ形の兄弟トリガー関数3本は今も予算無しで動いている**(2026-08-18 実読):
  - **`refreshClicks`**(毎時)= `for (URL行) { … Utilities.sleep(100) }`。1URLあたり100ms待機×行数。時間予算 **無し**。
  - **`refreshEngagement`**(毎時)= `for (25件バッチ) { fetch … Utilities.sleep(200) }`。行数に比例。時間予算 **無し**。
  - **`runReservations`**(5分毎)= `for (予約行) { … Utilities.sleep(300) }`。予約数に比例。時間予算 **無し**。
- 3本とも「1件ごとにsleep＋行数比例ループ＋硬い6分上限」= **INC-116と同じ骨格**。記録が育つ(投稿・URL・予約が増える)ほど6分に近づき、越えた日に静かに全滅する。**これは"まだ起きていない同型再発"=作成時に門を置く価値がある**(番犬型・複製判断型と同じ「1箇所直して兄弟に残る」型)。

## 不変条件(守れているか機械で見る)
- **I1**: **トリガー配下(timeBased/everyMinutes/everyHours)で走る関数**の中で、シート行・URL・予約など**入力量に比例して伸びるループ**を持つものは、**関数先頭で `t0=Date.now()` を採り、ループ内で `Date.now()-t0 > BUDGET` を超えたら打ち切る**枠を持つ。
- **I2**: 打ち切りは**冪等**にする=打ち切った残りは次回実行で続行できる(未処理は消さず次tickで再走査)。★打ち切っても、その回の**必ず到達すべき終端**(例=ピーク永続化)へは抜ける配分にする(INC-116の「残り1分で必ずピーク到達」)。
- **I3**: `Utilities.sleep(N)` を**ループ内**に持つトリガー関数は、**sleepの総量(N×想定件数)が硬い上限に収まるか**を見積もる。収まらない可能性があるなら予算必須(sleepは待つだけで6分を食い潰す最短経路)。

## 機械で見る案(改修αへ渡す検査の下書き)
CI門(`check_*.mjs` 群)と同じ**ベースライン凍結方式**で1本足す。対象は `gas/コード.gs`:
```
# ① トリガー登録(ScriptApp.newTrigger('fn').timeBased()...)される関数名を集める。
# ② その各関数の本体に、(a) 行数/URL/予約に比例するループ(for/forEach/getValues後の反復)や
#    (b) ループ内 Utilities.sleep( があるのに、(c) Date.now()-t0 系の打ち切りが無い ものを赤にする。
# ③ 既存の予算あり(snapshotStats)はホワイトリスト。新規にトリガー関数へ重いループを足したら
#    「時間予算(Date.now()-t0 打ち切り)を対で書け」と警告する=新規混入だけ止める。
```
検査の芯= **「トリガー配下の行数比例ループに、時間予算の打ち切りが欠けていたら赤」**。★静的検査なので「本当に6分を超えるか」は測れない=**"予算の有無"だけを見て、越えるかの判断は人間へ回す**(過検知許容・fail方向は警告)。
