# コード面プリフライト《番犬》= 外へ出る待ちに時限を付けないと「保存中…」で永久固着する

> ★細粒度(コード面)skillの2本目。Chami依頼 2026-08-16(msg=1538456267956428851=「もっと細かいプログラムのとこまで広げて」/ msg=1538537187253944393=Fable 5で棚卸し)を受け、Fable 5の棚卸し裁定で**JS側の作法に門がゼロ**と出た穴の1本目。型は自室・実装(検査の配線)は改修α。

## 何を止めるか(1行)
**`fetch()` や IndexedDB の要求を「時限(AbortController・番犬タイマー)無し」で新規に書くと、応答が返らない時に「保存中…」「取得中…」の表示が永久固着する。** 待ちに上限を付けないコードは「たまに遅い」ではなく「二度と返らない」になる。

## 実測した再発(=この型が要る証拠)
- **裸fetchの現在値**= `js/`+`core/` に `fetch(` が **62箇所**(js 57・core 5、17ファイル)。同一ファイルに AbortController/`signal:`/abortタイマーが在るのは **3箇所だけ**(`fanza-core.js`×1・`bluesky.js`×2)。残りは時限が無い。
- **同型の固着インシデントが並ぶ**(インシデント.md)= INC-108(fetchタイムアウト未設定でフリーズ)/ INC-116(応答待ちが返らず「保存中」固着)/ INC-125(fetch1回のみ・失敗を素通し)/ INC-132(cursor走査の永久待ち)/ INC-134(多重再試行で待ちが積む)。**待ちの時限**という同じ芯を、発症のたびに個別対処してきた。
- save-path型(`preflight_save-path-single-authority.md`)は「どこへ着地するか」を守るが、**通信・IDBの待ちが返らない**問題は別軸で未防御。

## 不変条件(守れているか機械で見る)
- **I1**: 外部/Workerへの `fetch()` は**時限とセット**で書く(`AbortController`＋`setTimeout(()=>ctrl.abort(), N)`、または時限ラッパ関数を通す)。裸の `fetch(url)` を新規に増やさない。
- **I2**: IndexedDB は**番犬付きの共通経路**(`core/idb-store.js` 等)を通す。新規の直 `indexedDB.open(` / 生 cursor 走査を、時限無しで足さない。
- **I3**: 待ちがUIの「…中」表示を持つなら、**時限到達時に必ず表示を元へ戻す/エラーへ倒す**分岐を同じコミットで書く(fail-open=固着より失敗表示が良い)。

## 機械で止める案(改修αへ渡す検査の下書き)
CI門3兄弟(`check_ui_ios.mjs` / `check_button_width.mjs` / `check_css_global_scope.mjs`=smoke.yml 44/50/57)と同じ作りで、**ベースライン凍結方式**の1本を足す:
```bash

grep -nE '\bfetch\s*\(' js/ core/
# 新規に増えた fetch 行が、同一関数内に AbortController / signal: / abort タイマーの
# いずれも持たない = 裸 なら赤。既存62箇所はホワイトリスト=回帰ゼロ。
# IDB側= core/idb-store.js 以外での新規 indexedDB.open( を赤(番犬済み経路へ寄せる)。
```
検査の芯= **「新規の裸待ちが1つでも増えたら赤」**。既存は据え置き(save-path型・CSS波及型と同じ「新規混入だけ止める」思想)。

## 直し方の定型(待ちを書く人がやること)
1. `fetch` を書いたら、**時限ラッパ**を通すか `AbortController`＋タイマーを同じ場所に書く。
2. IDBは**共通ストア経由**にする(直 open を新規に足さない)。
3. 「…中」表示を出したら、**時限到達で必ず戻す/失敗表示にする**枝を同じコミットで書く。
