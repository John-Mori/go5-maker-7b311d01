## 2. skill化の判定基準(全部を skill にしない)

skillが効くのは **①手順が固定でき ②忘れると事故になり ③機械が自動で防いでいない** ものだけ。
- 口調・呼称(101件)は**既にゲートが自動で書き直す**=skillは不要(二重になるだけ)。
- 版ずれ(23件)は **go5-deploy** が既に持っている=**増やさない**。
- 逆に「台帳」「検査」「載せ替え」「無言死」は**人の記憶に依存したまま**で、再発が続いている。

## 3. 候補(番号でそのまま選べる形)

1. **《記録》ledger-append** — 台帳JSONLへの追記と close の手順を1本に。生JSON手打ち禁止・
   `jsonl_store.append_jsonl` / `close_item.py` 経由・`--fixed` は機械が解ける在りかのみ・
   commit hashは受理されない。**根拠= 85件 + 実害2件**(2026-08-12 confirm 2件消失 / 2026-07-17 `ts='t'` 汚染)。
2. **《載せ替え》daemon-reload-check** — 常駐が読むものを足したらC-042の経路を同時に決める。
   `daemon_keeper.WATCH_FILES`(現在9本)へ足したか・都度読みか・keeper自身は監視外なので
   `reload_keeper.py --detach` が要るか。**根拠= 43件**(裁定C-042そのものが「また忘れた」から生まれた)。
3. **《検査》test-must-fail** — 検査/テストを足したら「**落ちること**」を1回見る。写像を変えたら
   その写像を読むテストまで一緒に動かす。**根拠= 61件**(常にPASSする検査は無いのと同じ)。
4. **《無言死》failopen-guard** — 端末側の非同期(IDB/fetch/Drive)を触る時、拒否・タイムアウト時に
   **黙って止まらない**側へ倒す型を固定。**根拠= 32件**(iOS Safariの真っ白は毎回この形)。
5. **《一本化》single-source-predicate** — 同じ判定(AI判定・onSale・候補判定)を複数経路が各自持つのを
   禁じ、`core/*-core.js` へ寄せる。**根拠= 14件**(v=759の「3経路の食い違い」がこの型)。
6. **《同期》sync-both-sides** — D1/R2/Drive/GASを片側だけ更新しない。**根拠= 67件**。ただし中身が
   案件ごとに違うので**skillより設計書向き**=優先度は下。

★1〜3は**手順が完全に固定できる**=skillの効きが一番良い。4〜5は判断が要るので短い型だけ置く形になる。
