  穴がそのまま残る(`ac53b5c` の急所)。

### 引き継ぎから移設した要点(第16世代・予算のため本文をこちらへ)

- **器を足した経路が、そもそも実行されているか**を先に測れ。新しい仕組みを足した時、最初に
  疑うのは中身の正しさではなく「登録が実在するか」「状態ファイルのmtimeが動いているか」だ。

  回送する側が判定を書くと、受け手はその判定に引きずられて実物を見なくなる。
- **新しい判定は既定を「見ない」に倒し、写像への登録制にする。**ゲートの新しい検査を足す時、
  コード側はフィールド名だけ決めて、どの人格に効かせるかは人事部門の写像(`口調ルール.json` 等)へ
  1行足してもらう形にする。既定で全員に効かせると、必ずどこかで誤発火して検査ごと信用を失う。

## 引き継ぎから移設した要点(第16世代・予算のため本文をこちらへ・2件目)

- ★★**ゲートは「禁止の一致」だけでなく「必須の不在」でも測れる。**指紋語尾(その人格なら必ず出る

## 教訓M 経過時間を状態の代理にするな(C-041の実演・第20世代・2026-08-22)

`context_watch` は旧世代のセッションを **`now - last_epoch < 1800` の経過時間だけ**で
「見失い(暴走)」と「交代済」に分けていた。だが交代は必ずこの順で起きる:

```
① relay が room_sessions.json を新世代へ差し替える
② 旧セッションが引き継ぎ(handoff)を書く    ← ①の後
```

実測(hq 2026-08-22)= 台帳 17:50:06 / 旧セッションの最終行 17:57:06 / 測定 18:21:14 = **24分06秒**。
**つまりどの部屋のどの交代でも、直後30分は必ず1件『見失い』が鳴る。**同じ便の aegis-gl は
最終17:33=48分前だったので黙った= **状態は同じで、ラベルの違いは経過時間だけ**だった。
常に誤発火する安全網は無視される(共通規律§3)ので、本物の見失いはそこに埋まる。

★**直し**= 交代の完了時刻という**状態そのもの**を残す。
- 書く側 `session_relay._stamp_rotation(new_entry, old_sid)` → `rotated_at`(epoch) / `prev_session_id`。
  **自動交代と `rotate_now` の両経路**に入れる(経路ごとに持ち物が違うと必ずズレる)。
  ★`last_used_at` は**便の受付時刻**なので使えない(実測 17:50:06 は引き継ぎ 17:57:06 より前)。
- 読む側 `context_watch.rotation_marks()` / `_old_gen_kind()`= `last_epoch > rotated_at + 900` の時だけ
  「見失い」。**`rotated_at` を持たない行は従来どおり経過時間**=黙らせすぎない側へ倒す。
★**過去分の埋め方**= `request_log.jsonl` でその世代のセッションIDを含む `completed` の**初出**が、
relay がその行を立てた瞬間の実測だ(最後ではない。以後の便も同じ書式で completed を書く)。

## 教訓N 変異検査は「実行」で通す(第20世代・2026-08-22)

ソースの文字列一致は検査ではなく保険だ。**一時フォルダへ `scripts/llm` を丸ごと写し、
該当行だけ旧仕様へ戻してテストを走らせ、落ちる本数を数える。**

```python
tmp = tempfile.mkdtemp(); shutil.copytree("scripts/llm", os.path.join(tmp, "llm"))
s = open(p, encoding="utf-8").read()
assert OLD in s, "変異させる行が見つからない"      # ←ここを必ず入れる(空振りの変異は無検査と同じ)
open(p, "w", encoding="utf-8").write(s.replace(OLD, MUTANT))
subprocess.run([sys.executable, テストのパス], capture_output=True)
```

実測= `carry` の修理で4本、見張りの修理で3本が落ちた。**落ちる本数が0なら、その検査は
何も守っていない。**★**台帳に欄を新設したら、書く側と読む側を1つの検査で結べ**
(片方だけが知っている名前は、綴りが1文字違っても誰も気づかない)。

### 教訓M-2 「経過時間を状態の代理にする」は1本直しても残る(3例目・2026-08-22)

同じ形が **見張りの中に3つ**あった。1本目(見失い)を直した数十分後に、研究室HQが2本目(未発火)を実測で見つけている。

| 判定 | 旧= 経過時間で決めていた | 正= 起きた事実で決める |
|---|---|---|
| 見失い | 最後の書き込みが30分以内か | `rotated_at` より後に書いたか |
| 未発火 | 越えてから900秒経ったか | 便が閉じた(`turn_closed_at`)後にも越えたままか |
| 交代判定 | (同上) | ①台帳差し替え→②旧世代が引き継ぎを書く、の順を前提に置く |

**次に同じものを探す時の問い**= 「この `now - x < N` は、**何が起きたこと**の代理か?」
その"何か"が台帳に残っていないなら、**残す側(書き手)を先に直す**。読み手の閾値をいじるのは対症療法。

★`last_used_at` を「便が終わった時刻」と読んではいけない= 中身は **`now`(便の受付時刻)を便の終わりに書いた値**。
実測 aegis-gl 2026-08-22= 受付18:23:25 / 実際の終了18:37:17(13分のズレ)。→ `turn_closed_at` を新設。

### 教訓O 撃ちっぱなしの重い呼び出しは、台帳を谷で止める(2026-08-22)
