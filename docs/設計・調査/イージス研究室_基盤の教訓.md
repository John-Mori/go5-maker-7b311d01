## 1. 設計の型(項目3の全文)

- **C-041 / C-042 / C-044 / C-046 はどれも自分が種**(中身は毎便の封筒に載る)。
- ★**この部屋の「差し替え点」**= `session_relay._run_claude`(叩く手)/ `queue_db_path()`(読むDB)/
  `defects_path()`+`set_defects_path()`(台帳の読み書き)。**読む先・叩く先・書く先を関数1本に切り出す**
  だけで本番の挙動は変えない。同型はこの形に揃えろ。検査から差し替えられる=実行で通せるようになる。
- ★**「今その状態が無いから検査できない」は、状態を作って渡す**(偽DBに滞留を作る/deadまで落とす/
  偽の便を差し込む/偽のスタンプ便を積む/一時ファイルの mtime を進める)。
- ★**移行(旧い判定から新しい判定への翻訳)は、その場で凍結しろ。**毎周回やり直す形にすると、直したはずの
  穴がそのまま残る(`ac53b5c` の急所)。
- ★★**台帳に印を足しただけでは誰も読まない。「読まれる場所に出るか」まで実物で見ろ。**実測=🔥の印を
  31行に足したのに、起動文に出るのは先頭12件で🔥は末尾に沈み**24件が1件も出ていなかった**(`33133a3`)。
  台帳・警報・レポートは**器に載せた時点で満足しやすい**。出口を必ず数えろ。
- ★**同じ物に複数の印が付く時は、重い方を先に処理しろ。**畳む鍵(msg_id)が同じなら**先に来た方だけが
  残る**=軽い方が勝つと重さが消える(🔥30件中25件が「再発」として積まれていた)。
- ★★**失敗を1つのカウンタで数えるな。箱を分けろ**(rc・is_error・課金の有無)= 429は返金して寝かせる／
  口座・認証は正直に失敗／rc=0で本文が空はセッション1本の故障／毒便は数えて dead。
  **★返金には必ず打ち止めを。「認証で死んだ」と「空で返った」を混ぜるな。**
- ★★**セッションが実際に何と答えたかは会話の記録で読める**=真因追跡の最短路
  (`request_log.jsonl` の `evidence` は**500字で切られる**)。
- ★**常駐の「版」は mtime でなく中身のsha1。見送った時も必ずログへ出せ**(無言の `ok` は沈黙)。
  **リースの起点は claim でなく本走の開始。暇判定は「リース ∪ 働き手の申告」**(`2a8e0fe`)。
- ★★**「死んだ」判定が1信号へ退行すると、守る仕掛けが殺す仕掛けに反転する。Windowsはプロセスの死を
  記録しない**=事後に痕跡を探す設計は負ける。
- ★**検査は「今の値」でなく「守りたい規則」で書く。「静かに緑を返す検査」(`catch { continue }`)は
  その場で塞げ。他部門が書いた「参照は全部で◯件」を数え直せ。**
- ★**機械の状態表示は人格の口で言わない**= dead通知・失敗告知は **メタルギアMk.II** 名義。
- ★**照合を完全一致1本で書くな。**名乗り・キー名・表記は必ず揺れる。外れた時に**黙って素通しする**造り
  だと誰も気付かない(`6b315b8`= 名乗り「ケヴィン・デ・ブライネ」と見出し「ケヴィン・デブライネ」の
  中黒1つで口調変換が丸ごと素通ししていた)。**受け皿を足す側で解け。データ側を裁定するな**(綴りや
  呼び名の正誤は人事部門の管轄)。★ただし正規化で2人が同じ形へ潰れたら**採らない**=人違いより素通し。
- ★**判定材料の「検出」と「規則」を同じ表に混ぜるな。**混ぜると規則を持たない相手にも意味が付いて誤爆
  する(`fa0733c`= `honorific_required_targets` に検出形を相乗りさせると「既定でさん付け必須」まで
  付いてきて、override を持たない話者が裸の呼びを出した瞬間に鳴る)。**別表に分ければ、override を
  書いたペアだけで判定が起きる**(C-035)。
- ★**常駐が読む物を足したら、載せ替えの経路も同時に決めろ**(C-042)。コードは
  `daemon_keeper.WATCH_FILES`(debounce90秒・最短10分)、データは**mtimeを見て読み直す**。片方だけ直すと
  「データを足しても常駐を落とすまで効かない」片肺になる(呼称側が 8/12〜8/15 これだった)。

## 2. 道具と環境の罠(項目3・7の実測)

- タスクスケジューラは対話シェルのPATHを継承しない(`-Execute 'python'` は 0x80070002 で静かに死ぬ
  =**絶対パスへ**)。子の stdout は cp932 なので `PYTHONIOENCODING=utf-8`。
- 「既存の赤か自分が壊したか」は `git worktree add -q --detach <dir> HEAD~1` で切り分ける
  (共有ツリーなので `git stash` は禁止)。
- `.ps1`(`supervise_daemons.ps1`・`revive_lab.ps1` 等)は**ASCII-only**。
- `grep -c` は0件で exit 1。**Bashツールの cwd は次の呼び出しに残る**(相対パスが突然外れる)。
- PowerShellのヒアストリング(`@'…'@`)をBashツールで使うな。長文は heredoc → `git commit -F`。
- `daily_reflection_trigger.py` を `--force` で走らせるな(実便が飛ぶ)。待つのに前景の `sleep` を使うな。
- `auditpol` は非管理者では 0x57。

## 3. やってはいけないこと(項目7の全文)

- ★★**共有ツリーで `git commit --amend` を使うな。★commit hash を測らずに書くな。**
- ★★**「鳴っていない」「動いていない」と言う前に、そのコードが載っているプロセスかを見ろ。
  ★そのログファイルが生きているかも見ろ**(止まったログを読むと真逆の結論が出る)。
- ★**測定そのものを疑え。**入れ子の引用符で「常駐0体」という嘘の数字が出た(実際は30体)。
  **おかしな数字はまず測り方を疑い、直るまで報告に載せるな。★他部門の完了報告も信じるな。**
- ★**前世代が手で撃った検証の痕跡を、本番の実物として数えるな。**★逆に**「ファイルが無いこと」を
  「起きていないこと」の代理にするな**(C-041を自分で踏んだ= `dead_letters.jsonl` 不在→「実dead未発生」
  と書いたが02:37に起きていた)。
- ★**検査が赤くなったら、まず検査の前提を疑え。**8/15= 他部門(人事)が「私」を禁止語へ足した結果、
  「『私』は鳴らない」という古い前提の検査が赤くなった。正解は実装を戻すことではなく**検査を反転**
  させることだった(その上で「俺」が鳴らない負の対照を足す)。
- ★**`git add` の前に他セッションが index に積んでいないか見ろ。**commit後は `git show --stat` で
  確かめ、混ざったら正直に言え。★存在しないパスを `git add` に混ぜるな(全体が中止される)。
  ★`local/` はgitignore=未追跡は他セッションの clean で消える。★**削除しない・退避する**(C-003)。
  台帳は追記のみ。★**書き換える前に `.bak`**。
- ★**背景待ちのgrepを「既に在る行」に当てるな**(開始時点の行数を控えろ)。★**背景ジョブは完了記録を
  残さず止まる**=当てにせず自分で見に行け。★`.claude/` への書き込みが権限で弾かれたら**迂回するな**=
  Chamiの手番として1行で出せ。
- ★**本番の部屋で検証を撃つな。**実物が要るなら自室で撃ち、本文に検証だと書く。★検査で偽物にして
  よいのは**外へ出る手だけ**(送信・起動・書き込み先・ログ)。**判定と分岐を偽物にしたら検査ではない。**
- ★**巡回を「積み直す」ために `reaction_watch.py` を丸ごと再実行するな**=各部屋へ**投函が飛ぶ**。
  過去分を直すなら `reaction_seen.jsonl` から対象を割り出し、台帳の関数を直接叩け(新規IDを出さない形で)。
- ★**人格・呼び名・characterfileの中身を自分で直すな**(人事部門の管轄)。俺が触れるのは**配線と受け皿**だけ。
