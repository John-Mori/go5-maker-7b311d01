## 1. 「生きた研究室」の定義(REQ be236859f3 / c77f913eaa の答え)

1つの部屋に**2つの担い手**が居る。混同が「話せてるのに死んだ扱い」の正体:

- **精霊(dept_daemon)** = 常時稼働。一次ack・軽い応答・キューのclaim。**これは生きている。**
- **本対応の消費者(relay consumer session)** = 対話セッション(窓)。重い便・文脈の要る返答を担う。**これが閉じていると「死んだ扱い」**。

→ `session_relay` を持つ17部屋は、`handle()`が消費者へ配送を試み、**失敗すると`ok=False`→`失敗(main回送済)`→`discord_inbox.jsonl`へ追記**(dept_daemon.py:4581-4584)。回送先(MAIN_INBOX)を読む生きたセッションが居なければ、そこで**無音**になる。

**復活方法(c77f913eaa)= その部屋の消費者セッションを開く**か、**§3のfail-openで精霊が代わりに喋る**。

## 3. 恒久修正の設計

### 3.1 relay無人時 fail-open(§3「沈黙が最悪の事故・fail-open→喋る側へ倒す」)
- **今**: 消費者不在→回送→(消費者居なければ)沈黙。
- **後**: 消費者不在を検知したら、**精霊が自前でキャラ応答を1本生成して返す**(劣化してもよい。沈黙よりよい)。回送は"生成も落ちた時"の最後段に降格。
- ★**核心のトレードオフ= 二重応答**(daipa-race-double-post)。生成後に消費者が復帰して二重に喋る事故を防ぐ:
  - (a) 生成の**直前と直後**に `session_presence.window_present()` を再確認(在席が立ったら生成を捨てる)。
  - (b) `session_relay._record(mid, dept, "daemon_answered")` で**答えた印**を残し、消費者側は同印のある便をスキップ。
- 対象= `session_relay:True` の17部屋。**hq/research-room の2室は回送しない設計(Chami「絶対やめてくれ」)なので除外**=1バイトも触らない。

### 3.2 回送センチネル(REQ 2ebfde7d45「自律的報告なし」の回送版)
- `discord_inbox.jsonl` の回送便で、**N分(暫定20分)本対応されていない**ものを検知→報告通知へ1通(report_pulseと同じ送信経路を再利用)。
- ★**前提= 「本対応済み」の印が要る**。無いと全回送便に誤発火する(ORG-42「常に鳴る警報は読まれない」)。→ 3.1(b)の`daemon_answered`と、消費者が返信時に押す`replied`印を**同じ台帳**に集約し、印の無い回送だけをアラート対象にする。**印の設計が先・センチネルは後**(この順を守る)。

### 3.3 drainゲート(HQ P0①)
- keeperが更新を検知→**全workerの新規claimを停止**→`inflight + 実子プロセス0`を待つ→**タイムアウトでも強制killせず通知のみ**。0fc11a5の`_inflight_depts()`(pending&lease_until>=nowで実測・DBエラー時None=延期)を土台に、maybe_reloadへ「drain中フラグ」を足す。

### 3.4 同一session_id排他(HQ P0②)
- resume前に`session_id`ロックを取得。**重複はnackか待機**(二重resume=二重応答の別経路を塞ぐ)。ロックは`local/queue/`配下のファイルロックで十分(単一ホスト)。
