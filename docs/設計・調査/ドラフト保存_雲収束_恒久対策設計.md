# ドラフト保存の「雲収束(eventual durability)」恒久対策設計

作成 2026-08-17 / 起点 Chami報告 msg1538754754824507473(①自動遷移せず ②動画DL準備中 ③再作成で画像消える)
思考=Fable 5 / 実装=Opus(C-043)。本書は再発案件の真因と段階的恒久対策の正本。

## 真因(Fable5診断・コード確定事実)
①②は別の顔をした**同じ構造欠陥**。「単一着地権威(Go5SaveGate)」は着地を**書いた瞬間**にしか検証しておらず、
iOSではIDBの読み戻し成功=そのセッション内の read-your-own-writes にすぎず**耐久性を意味しない**。
今回の個体=「IDBレーンだけ着地→commit確定→後からiOSがIDB実体を丸ごと退避。R2レーンは作成時に失敗したまま
誰も返済していない」。だから「一覧には確定しているのに動画もサムネもどこにも無い」矛盾が成立する。

- **② DL準備中**: resolveVideoBlob_ → IDB空(fail-open) → resolveVideoFromR2_ が45秒レースを待ち切ってnull → alert。
  armButtonは60秒まで「準備中…」。無限ではなく45〜61秒の固まり→alert。R2に無い真因=作成時cloud PUT失敗を
  `.catch(function(){})`が握り潰し、修復役 sweepVideoMirror_ は**IDBから読んで上げ直す**設計=IDB喪失後は構造的に修復不能。
- **② サムネ確認中**: stock_t_/mirror/stock_prev_/stock_img_ 全滅。fallback連鎖にR2(go5src)枝が無かった。
- **① 非遷移**: navTimer **25秒固定** vs レーン最悪(local set+get最大32秒 / cloud=core/sync.js api()は**タイムアウト無し=無期限ハング**)。
  期限がレーン最悪所要より短い=重い日は「最終的に成功する保存」でもholdが先に出る。cloudハング+localrejectだと
  onBothFailedも発火せず(bothDoneが永遠に未settle)着地シグナルが一切来ない。

## なぜ過去5回すり抜けたか
書く瞬間/読む瞬間の防御ばかりで、**commit後に雲へ必ず収束させる義務(eventual durability)を誰も持っていない**。
ensureVideoMirror_失敗は無言リトライ待ち(sweep頼み)、sweepはIDB喪失後は空振り。navTimer25秒vsレーン∞の期限逆転も未修正。

## 恒久対策(段階導入)
方向=「R2を源泉・IDBはキャッシュ」。ただしcommit条件は現状維持(UX優先)、雲収束を**返済義務**として永続化する。

### 済(2026-08-17・v=836/837 = commit d694ed7 ほか)
- ③ 元画像を作成時にメモリから直接R2(go5src)へ控える(ensureSrcMirror_)。再作成/Drive保存/サムネがR2から拾える。
- ③副作用の緩和: 元画像PUTを6秒遅延=動画の着地を先に通す(上り帯域の食い合いで①②を悪化させない)。
- P3: サムネfallback連鎖の最後に go5src のR2取得を追加(「確認中」を絵へ)。
- 診断: DL失敗alertに 雲同期の設定状態 + go5_landing_log の当該着地理由 + id を載せる(次のスクショ1枚で切り分け)。

### 済(2026-08-17・v=838 = commit 73b1ebc / 思考Fable5・実装Opus C-043)
- **P1**: core/sync.js api() に opt-in AbortController タイムアウト(putBlobR2Atが 60秒指定)。state同期(pull/push)は不変=無期限のまま。
  雲レーン(verifyCloudVideoWrite_→ensureVideoMirror_→putBlobR2At)が必ず決着=bothDoneが沈黙ハングしない。
- **P2**: navTimer 25秒hold を撤廃。25秒=進捗トースト(showSaveWait_)のみで判定は変えない。hold は onBothFailed(両レーン失敗確定)か 75秒の最終安全網だけ。
  遷移は従来どおり localLanded/cloudLanded(実物着地検証済)の時だけ=8/15全滅回帰は構造的に不可(save-gate.js decide()は無改変・fuzzテストも不変)。
  「前は遷移していた」を体感で戻す本丸=iPhoneの細い上りでPUTが25秒超でも、着地した瞬間に自動遷移する。
- **②即DL**: warmNewestVideos_ で最新2件のドラフト動画を先読み(手元IDBに実体が有れば何もしない/無い時だけR2取得→IDBへ書戻し)。
  次のDLタップは手元から即。逐次・非表示タブ不動作・fail-open。goDraft_はlocation.href全リロードのためメモリキャッシュは不採用(Fable5判断)。

### 未(残・任意)
- **P0**: 雲着地の返済台帳(go5_vid_debt)。localのみ着地は meta.cloudLanded=false+負債レコード。sweepを負債駆動にし、
  `/api/img/has` で実在確認してから消込+cloudLanded=true。**IDBに実体無し+負債残**=commit後喪失を初検知→
  landing_logに `lost-after-commit`、カードに「⚠実体喪失(再作成が必要)」バッジ=沈黙で確認中に見せない。
- P4(任意): firstVideoLanding_ でR2 PUTを主・IDBを並行キャッシュに位置づけ(実質はP0の意味論変更で足りる)。
