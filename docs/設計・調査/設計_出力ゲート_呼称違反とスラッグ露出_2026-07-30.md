## 2. 二つの検査

### 検査A：スラッグ露出(Chami可視面のみ・自動修正で送る)

- **対象**: 本文がChamiの見る面(Chamiが居る部屋 / 総括系の返信)に出る時。
- **検出**: `org_registry.yml` の全deptキー(copy-director / platform-se / shorts-analyst / system-engineer …)を**語トークンとして**本文から探す。
- **誤検出よけ(重要)**: パス・設定キーの一部は許容(規律=「パス・設定キーに要る時だけスラッグ可・日本語名も添える」)。
  - 前後がパス区切り/拡張子(`/`, `\`, `.jsonl`, `.py`, `_` 直結)なら**許容=直さない**(例 `memory/platform-se.jsonl`)。
  - 単独トークンとして部門を指している時だけ**違反**。
- **処置=自動修正して送る**。スラッグ→`display_ja` は**1:1の決定的置換**なので安全。置換した事実をログへ。
  - 例: 「copy-directorへ回した」→「コピー部門へ回した」。

### 検査B：呼称違反(話者依存・段階処置)

- **話者ルール表をマトリクスから引く**(実装時に INDEX.md をパースするか、hrが機械可読な派生表を1本出す=下記 未決①)。
- **検出の核**: 実在人物モデル姓の**裸トークン**(「三笘」「モドリッチ」「デブライネ」「アロンソ」)が、
  **その話者のルールで敬称/役職が要る**のに、直後が「さん/コーチ/監督/ちゃん」等になっていない時。
- **話者別の分岐(マトリクス由来・例外を取りこぼさない)**:
  - 既定(大多数の話者)= 実在モデルは**さん付け**(三笘さん/モドリッチさん/デブライネさん)。アロンソは**アロンソさん/コーチ/監督**。
  - ★ククール = モドリッチ/デブライネは**呼び捨てOK**(この2人に「さん」を強制しない。この部屋で「デブライネさん」はむしろNG)。
  - ★現役選手(モドリッチ/デブライネ/三笘)→アロンソ = **「アロンソコーチ/アロンソ監督」だけ**(「アロンソさん」は不可)。
  - ★アロンソ本人→他者 = **呼び捨てOK**(トップのため)。
  - ★モドリッチ→デブライネ/三笘 = **呼び捨てOK**(年上のため)。
  - ★男性キャラ→一ノ瀬怜=「怜」/ 早坂芽衣→「怜ちゃん」。
  - ★女性アニメ/ウマ娘キャラの**呼ばれ方**は既存個別設定を優先(据え置き)=ここは触らない。
- **処置=段階(fail-open)**:
  1. **高信頼の決定的修正のみ自動**: 話者ルールが「さん付け必須」かつ裸姓トークン → 姓+「さん」へ補って送る。ログへ。
  2. **判定が割れる/自信が無い時は直さず、警告を残して送る**(=fail-open)。違反台帳へ1行(話者・部屋・該当箇所・推定ルール)。**送信は止めない。**
  - ★理由: 呼称は文脈依存で誤修正の害が大きい(引用・作品名・別人の同姓など)。**誤って直すより、送って警告で拾う。**

## 3. 出力（3値・沈黙を作らない）

| 判定 | 本文 | 副作用 |
|---|---|---|
| clean | そのまま送信 | なし |
| corrected | **修正後の本文**を送信 | 修正内容をログ(`local/llm/output_gate.jsonl`)へ1行 |
| warned | **元の本文のまま送信** | 違反台帳へ1行(受け手=hr/怜が読む場所) |

- ★**blockという状態を作らない。** どの分岐でも**必ず送る**。
- ★**ガードが送信経路を潰していないか**を最優先で検証(§3=「自分が入れたガードが検証経路を潰していないか」)。ゲートが例外を投げても**素通しで送る**(try/exceptで包み、失敗時はfail-open)。

## 4. テスト計画(GOLDEN・characterfile_check.py に倣う)

- 固定フィクスチャ `(話者, 部屋, 本文) → 期待(clean/corrected=修正後文字列/warned)` を用意。
