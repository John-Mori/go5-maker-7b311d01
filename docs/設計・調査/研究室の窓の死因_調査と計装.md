### 3.2 `scripts/_daemons/lab_window.cmd`(新規)

`cmd /k` を証人にして、claude.exe の終了コードを**死んだその瞬間に** `local/_lab_claude_exit.log` へ1行書く。

- **バッチファイルの中でしか `%errorlevel%` は本物にならない。**コマンドライン上(`cmd /k a && echo %errorlevel%`)では
  解析時に一度だけ展開され **常に0** へ潰れる。遅延展開(`cmd /v:on` + `!errorlevel!`)は
  起動プロンプト中の `!` を食うので使わない。
- ★罠= `echo ... exit=%LAB_RC%>> file` は展開後 `exit=1>> file` になり、cmd が **`1>>` をストリーム1の
  リダイレクト**と読む=コードが消えて `exit=` で終わる(実測)。**`>>` を行頭に置く**ことで回避。
- claude.exe のパスは **引数1としてコマンドライン上に残す**。§2.5 の死骸フィルタが
  `\.local\\bin\\claude\.exe` で拾っているため、中へ隠すと**死骸が永久に見えなくなる**。
- 常駐ゼロ・管理者権限ゼロ・**載せ替え経路も不要**(spawn 毎に読み直される)=C-042 に新しい借金を作らない。

- 書き手= `scripts/llm/inbox_waiter.py` の `claim_lab_owner()` → `local/llm/lab_owner_pid.txt`。
  `--name main` の時だけ書く(部門名では何も書かない=実測で確認)。

## 6.2 ★transcriptの文字列で判定する案は、本番で誤爆させて棄却した

最初に実装したのは「自分のtranscriptの中で `inbox_waiter.py --name main` を実行しているか」だった
(`progress_mark.py` が ORG-17 で確立した判定の流用。tool_use の input.command だけを見る・
python実行を要求する、という防御も両方入れた)。**実測は 25本中1本だけが一致**し、筋は良く見えた。

**それを本番へ入れた3分後、この機能をデバッグしていた自分(aegis-gl)のセッションが
自分を司令塔と誤認した。** 17:21:23 に `lab_session_id.txt` を自分のIDで上書きし、
17:22:46 に実物の `lab_tool_pulse.txt` を打った。原因は単純で、**判定に使う文字列を
自分でコマンドラインに書いたから**だ(誤検出の的当てをするコマンドの中に literal が入っていた)。

→ 文字列は誰でも書ける。**親子関係は書けない。** 判定材料を替えた。
