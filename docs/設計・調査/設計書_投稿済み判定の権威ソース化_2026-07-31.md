# 設計書: 候補タブ「投稿済み✔」pill の根本原因と恒久対策(権威ソース化)

策定 2026-07-31 / 分析 Fable 5(最大工数)/ 実装 Opus。
発端= Chami依頼「投稿済みなのに✅が入らない場合の対処法が無い。偽陽性(投稿してない側に✔)含めて、こちらの手番なしで根治せよ」。

---

## 1. 構造的診断(根因)

pill判定の正が **端末ローカルの短縮URL履歴(`short_hist__<acct>` + `verify_manual__<acct>`)** にある。これは
**クラウド同期されない揮発データ**(core/storage-keys.js の legacyNoSync)。一方、投稿の全経路(今すぐ/予約/無人/動画後自動)が
書き込む権威記録は **GASスプレッドシートの `記録_ch1`/`記録_ch2`(チャンネル別に物理分離)**。この2ソースの分離を、移動・DID矯正・
シート再マージ・サニタイズの4補修＋手動ボタン2つ＋手動オーバーライドで事後補正しているのが構造欠陥。

- 偽陽性(A): 誤ったバケットに記録が入り所有ガード(videoId prefix / account欄)をすり抜ける。無印記録は fail-open で数える。
- 偽陰性(B): **端末分断が最大**=別端末で投稿→この端末の short_hist は空→✔出ない。現在の回復は手動「📥シートから復元」= Chamiの手番。ほか cid食い違い(Books旧数字ID↔新content_id)・workUrl欠落・200件上限・移動系がaccountを書き換えない。

## 2. 恒久対策= 「シート権威索引 + ローカル新鮮分マージ + fail-openフォールバック」

判定を GASシート(ch別分離)から引く。**記録_ch2 に無ければ acc2 は未投稿**(偽陽性の構造的消滅)＋**全端末が同じシートを読む**(偽陰性の構造的消滅)が単一変更で同時成立。GAS未設定/通信失敗は従来ローカル判定へ完全フォールバック(可用性優先・現状悪化ゼロ)。

### 2.1 GAS `action=posted_cids`(読み取り専用・軽量)
```
GET <exec>?action=posted_cids&channel=both&callback=cb
→ cb({ ok:true, version, at, acc1:[{c:cid, w:作品URL, v:post_id, t:日付}], acc2:[…] })
```
- historyItems_ の縮小版(全行・4列射影・c/w両空行は除外)。
- サーバー側prefixガード: `post_id` の acc-prefix がタブと矛盾する行はそのタブ応答から除外。
- GAS_VERSION バンプ→`GASを反映.bat`(exec URL不変・`?ping=1`検証)。

### 2.2 candidates.js 索引を3層に
- **権威層**: `posted_sheet_v1` キャッシュ(端末別・Go5Util.jsonp + bsky_gas_url・10分TTL・stale-while-revalidate)。
- **ローカル新鮮層**: `ts>fetchedAt` または所有スタンプ陽性一致のみ採用(権威があるとき無印はfail-closed=A-3消滅)。
- **レガシー層**: 権威が一度も取れない時は現行ロジック(fail-open)。
- 索引合成を純関数 `buildPostedIndex_(authorityItems, localItems, account, offMap)` に切り出し、`tests/test_posted_index.js` 新設。
- `postedMatchForCand_`/`acctBadgesHtml_`/`postedDatesHtml_`/`openPostedDetailModal_` は無改修(索引の中身が変わるだけ)。
- 🚫オーバーライド `cand_posted_off` は残す(シート自体の誤行への即時逃げ)。sync許可リストへ追加し全端末波及。

## 3. 実装ステップ

- **S1(最小手・B-1端末分断とAの大半が消える)**: GAS `posted_cids` 新設＋バンプ＋反映 / candidates.js `fetchPostedAuthority_`＋`buildPostedIndex_`＋`postedIndexFor_` 3層化＋テスト / bump→deploy。
- **S2**: 移動系4箇所＋`addCompletedPost_` に account スタンプ / Books 双方向キー / `cand_posted_off` を sync許可リストへ。
- **S3(任意)**: 🚫押下でシート行も `action=delete` 併発(confirm文言に追記)。

## 4. 回帰防御
short_hist依存(投稿履歴タブ表示・ランキング・リビルド印・シート同期)は pill判定と独立=無影響。重複投稿防止(P0-3)は pill精度向上で強化方向。fail-open で GAS未設定環境は現状維持。prune はシート=権威を削る操作なので confirm文言に「✔も消える」注意を追記推奨。

詳細な経路列挙(A-1〜A-4 / B-1〜B-6)と行番号裏取りは本design策定時のFable5分析に準拠。
